Orquestación de Datos y Algoritmos

Este diagrama muestra cómo las APIs de múltiples fuentes alimentan el pipeline de Machine Learning, cómo el Científico de Datos entrena y publica modelos, y cómo el Portal Morgan & Morgan consume los resultados desde la base de datos central.

1. Ingesta desde APIs
Fuentes Externas

El sistema consume datos de APIs de terceros y sistemas internos:

  • API Amadeus (reservas, viajeros)
  • API MNet (clientes, cuentas)
  • Sistemas Legados / Batch CSV
  • Listas de Sanciones, PEP, Control Lists

Cada llamada se normaliza y se guarda en una Capa de Ingesta (Raw Layer)

2. Laboratorio de ML
Científico de Datos

El Científico de Datos trabaja sobre los datos normalizados:

  • Explora y limpia datos (EDA)
  • Define features de similitud (nombre, teléfono, dirección, etc.)
  • Entrena modelos de detección de duplicados
  • Define umbrales de decisión (ej. 85%)

El modelo entrenado se publica como:

  • Job batch (procesos nocturnos)
  • o API de Scoring (en tiempo real)
3. Data Lake / DB
Persistencia

Los resultados del modelo se guardan en una base de datos central:

  • Tabla de grupos de duplicados
  • Scores de similitud por par/grupo
  • Flags de riesgo (PEP, sanciones)
  • Bitácora / Audit Trail

Esta capa actúa como Single Source of Truth para el portal.

4. Portal Morgan & Morgan
Frontend / APIs

El Portal de Integridad de Entes se conecta a la DB central vía APIs internas:

  • API /grupos-duplicados (bandeja de casos)
  • API /detalle-grupo/{id} (modal de revisión)
  • API /fusionar (confirmar fusión)
  • API /falsos-positivos (lista de excepciones)

El usuario ve los resultados, decide, y el sistema devuelve las decisiones a la misma base de datos (actualizando estados y auditoría).

Ejemplo de Flujo desde el Portal 
// Frontend (index.html) consulta grupos detectados por ML
GET /api/grupos-duplicados?compania=201&umbral=0.85

// Respuesta de la API (datos desde BD alimentada por modelos)
[
  {
    "idGrupo": "GRP-007",
    "ente": "Patricia Elena Martínez",
    "companias": ["201", "203"],
    "similitud": 0.87,
    "estado": "Requiere Taller Técnico",
    "riesgos": ["PEP", "Watchlist"]
  }
]
Ciclo Completo
  • 1. Ingesta: APIs externas → Capa Raw
  • 2. ML: Científico entrena modelos
  • 3. BD: Resultados y riesgos persistidos
  • 4. Portal: Consulta vía APIs internas
  • 5. Decisión: Usuario marca fusiones
  • 6. Auditoría: Retroalimentación a BD
